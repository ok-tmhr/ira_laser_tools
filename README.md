# ira_laser_tools

This library includes some tools for laser handling in ROS 2. At the moment two nodes are available:

- laserscan_multi_merger
- laserscan_virtualizer

Both use part of the pointcloud_to_laserscan code available in ROS 2.

## laserscan_multi_merger

Allows to easily merge multiple, same time, single scanning plane, laser scans into a single one; this is very useful for using applications like SLAM, localization on vehicles with multiple single scanning plane laser scanners, as these applications require just one laser scan as input. The scanning planes need to be approximately the same. The resulting scan will appear generated from a single scanner disregarding actual occlusions as seen from the merged scans; for instance, consider the case of 2 scanners mounted on the 2 front corners A and B of a rectangular vehicle (we live in 2D); each scanner gives out a 270 degrees scan, from along the long side of the vehicle going backward to toward the other scanner. The merged scan will appear as generated from a virtual scanner positioned in C, halfway A and B, and measuring the same measures of the merged scans, irregardless of the occlusions that would apply to a real scanner positioned in C.

### Parameters

Parameters are managed using the ROS 2 parameter library. Default values are defined in `param/laserscan_multi_merger_parameters.yaml`.

For detailed parameter descriptions, see [laserscan_multi_merger_parameters.md](doc/laserscan_multi_merger_parameters.md).

### Launch Files

- `laserscan_multi_merger.launch.py`: Python launch file with parameter file support
- `laserscan_multi_merger.launch.xml`: XML launch file
- `laserscan_multi_merger.launch.yaml`: YAML launch file
- `laserscan_multi_merger_container.launch.py`: Component container launch (Python)
- `laserscan_multi_merger_container.launch.xml`: Component container launch (XML)
- `laserscan_multi_merger_container.launch.yaml`: Component container launch (YAML)

## laserscan_virtualizer

Allows to easily generate virtual laser scans from a pointcloud such as the one generated by a multiple scanning plane laser scanner, e.g., a velodyne scanner. The only requirement is the rototranslation between the virtual laser scanner and the base frame to be known to TF.

### Parameters

Parameters are managed using the ROS 2 parameter library. Default values are defined in `param/laserscan_virtualizer_parameters.yaml`.

- `base_frame`: Reference frame which laser(s) are related to (string, default: "base_link")
- `cloud_topic`: Input point cloud topic (string, default: "/cloud_pcd")
- `output_laser_topic`: Virtual laser output topic, leave empty to publish on virtual laser names (string, default: "/scan")
- `virtual_laser_scan`: List of virtual laser scan frames (space separated) (string, default: "scan1 scan2")
- `angle_min`: Minimum angle of virtual scan (radians) (double, default: -3.14)
- `angle_max`: Maximum angle of virtual scan (radians) (double, default: 3.14)
- `angle_increment`: Angular resolution of virtual scan (radians) (double, default: 0.0058)
- `scan_time`: Time duration of a complete scan (seconds) (double, default: 0.0)
- `range_min`: Minimum valid range for measurements (meters) (double, default: 0.0)
- `range_max`: Maximum valid range for measurements (meters) (double, default: 25.0)

### Launch Files

- `laserscan_virtualizer.launch`: Legacy XML launch file

## Building

This package is built using colcon and supports ROS 2 Jazzy.

```bash
colcon build --symlink-install
```
